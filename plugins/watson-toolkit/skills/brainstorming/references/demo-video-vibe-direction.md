# Demo/trailer vibe direction notes

Use when brainstorming app demos, launch trailers, product teaser videos, or other creative media artifacts.

## Core lesson

A proof-of-surface video is not automatically a compelling demo. Screenshots, QA overlays, red boxes, equal-duration slides, and literal page tours may prove the app works while failing to create desire.

For Jeremy-facing demo media, separate these artifact classes early:

| Artifact class | Purpose | Typical shape | Failure mode |
|---|---|---|---|
| QA proof reel | Prove surfaces exist and flows work | annotated screenshots, exact blockers, slow walkthrough | looks internal, not exciting |
| Founder walkthrough | Build trust and explain actual behavior | real interactions, slower pacing, voiceover, clear UI | too much exposition for launch/social |
| Product teaser | Drive interest fast | fast pacing, strong type, minimal UI, hook/stat/reveal | too vague if no product proof |
| Launch trailer | Create emotional pull | cinematic copy, selective UI glimpses, abstract motion, music/VO | can become generic if not grounded in real product |
| Hybrid | Balance desire + credibility | teaser open, real interaction middle, strong close | needs careful pacing |

## Signals that the current cut is not working

- User says the “vibe” is not done, not exciting, or not demonstrative.
- The video feels like a QA artifact rather than something that would drive interest.
- Red boxes, browser annotations, accessibility overlays, or test highlights are visible.
- Every screen is held for the same duration.
- The edit reads as “here are pages” instead of “here is why this matters.”
- Empty states are shown without framing them as readiness, restraint, or product philosophy.

## Better opening question

Before rendering a second pass, ask for the intended artifact class rather than guessing polish level:

> Which direction should this cut push toward: product teaser, founder walkthrough, launch trailer, or hybrid?

If the user picks **launch trailer**, reduce literal product tour beats and lead with feeling: situation → tension → product reveal → human outcome.

## Production guidance

1. Remove QA overlays before any taste-facing cut.
2. Use real product surfaces as selective proof, not the entire narrative.
3. Build pacing around the emotional arc, not a list of captured pages.
4. Use the project’s brand system as edit language: typography, color, copy rules, motion tone.
5. Prefer fewer, stronger captions over explanatory lower-thirds.
6. Spot-check rendered frames visually for clipped type, awkward crops, and internal-tool residue.
7. State confidence honestly: call early outputs directional prototypes until the vibe is actually there.

## LOCALS-specific example from 2026-06-02

A rough slideshow proved the LOCALS surfaces existed, but Jeremy rejected the vibe: red QA boxes and flat pacing were not exciting or demonstrative. A better next cut was a launch-trailer direction: cinematic copy around landing in a city, real people nearby, invite-only room, selective map/city/profile glimpses, and a short emotional close.
